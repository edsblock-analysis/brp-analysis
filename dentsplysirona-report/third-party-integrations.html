Why two evidence methods: a static scan finds everything hard-coded in the HTML (Scene7, Coveo, Salesforce, payment config, external app links). But Adobe Launch injects analytics/marketing tags at runtime — so ContentSquare, Heap, Google Ads/DoubleClick and Zoovu only appear when the page actually executes. Playwright network capture caught these; a static-only review would have missed them.
Runtime-only integrations (invisible in static HTML — found via live capture):
  • ContentSquare — Behavioral analytics: session recording, heatmaps/zoning, custom variables (site section, page category, page name, country, login state). (c.az / k-us1.az / c.us / srm.af .contentsquare.net pageview + recording + events beacons on every sampled page (injected via Launch — NOT in static HTML).)
  • Heap Analytics — Product/event analytics with auto-capture and user properties. (c.us.heap-api.com/api/capture/v2/track + add_user_properties on every sampled page (via Launch).)
  • Google Analytics / Google Tag Manager — Web analytics + tag orchestration (a GTM container runs alongside Adobe Launch). (www.googletagmanager.com (gtm=45...) firing google.com/ccm/collect page_view beacons.)
  • Google Ads + DoubleClick (Conversion & Remarketing) — Ad conversion tracking + remarketing audiences. (google.com/ccm/collect & rmkt/collect for AW-876574706; ad.doubleclick.net/ccm/s/collect; googleadservices.com.)
  • Zoovu (Guided Selling / Product Advisor) — Guided product selection / recommendation advisor. (Console "ZOOVU: Waiting for digitalData to be fully loaded" on shop brand pages (clientlib-invoked).)

Adobe Commerce Integration Framework (Adobe I/O Runtime)
Commerce Static+Runtime
 Site-wide Serverless bridge (Adobe CIF) that dispatches storefront GraphQL calls to the SAP Hybris commerce backend. 58919-cifintegration.adobeioruntime.net/api/v1/web/hybris-graphql/dispatcher (+ /ms-layer/rest). GraphQL product/price/cart/customer requests proxied to Hybris; SSO logout endpoints. EDS commerce blocks call this same GraphQL dispatcher client-side. Keep the I/O Runtime action or point EDS at the equivalent endpoint. Core to any commerce-in-EDS decision.

Full rebuild is out of scope unless DS confirms.

 Site-wide Site search + type-ahead suggestions, product listing (PLP) search, and recommendations. Relevance/index config owned by DS search team (out of scope).
